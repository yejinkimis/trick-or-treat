# 똑똑 할로윈

픽셀 마을을 돌아다니며 친구 집 문을 두드리고 사탕을 주고받는 할로윈 게임. 코스튬, 호박 바구니, 타이밍 노크, 장난(trick), 뿅망치, 방명록, 집 꾸미기, 지붕 그림, 채팅이 있다.

## 혼자 돌려 보기

`prototype/trick-or-treat.html`을 파일로 열면 연습 모드로 뜬다. 가짜 친구 두 집과 돌아다니는 봇(테스트친구)이 있고, 기록은 새로고침하면 사라진다. 계정 화면까지 보려면 아래 로컬 서버로 연다.

## 닉네임 계정과 로컬 개발

게임 HTML은 계속 `prototype/trick-or-treat.html` 하나를 원본으로 쓴다. Vercel 배포용 `dist/index.html`은 빌드할 때 원본을 복사해서 만든다. 인증 API와 Firebase 설정은 별도 서버 파일에 둔다.

Node.js 24와 Java 21이 필요하다. 패키지를 설치한 뒤 터미널 두 개에서 에뮬레이터와 게임 서버를 각각 실행한다. 로컬 서버는 항상 `demo-trick-or-treat` 에뮬레이터만 사용하며 실제 Firebase 프로젝트에는 연결하지 않는다.

```sh
npm install
npm run dev:emulators
```

```sh
npm run dev
```

브라우저에서 `http://127.0.0.1:4173`을 연다. Emulator Suite 화면은 `http://127.0.0.1:4000`에서 볼 수 있다. 배포 빌드는 `npm run build`로 만들고, `npm test`는 게임 회귀와 인증 정책 검사를 실행한다. `npm run test:emulator`는 인증·Firestore 에뮬레이터를 띄워 닉네임 경합, 잘못된 비밀번호, 기기 간 같은 UID, 보안 규칙을 검증한다.

가입할 때 서버가 고유 UID를 한 번 발급한다. 닉네임은 유니코드 NFKC 정규화 후 대소문자와 연속 공백을 무시해 중복을 막는다. 비밀번호는 8자 이상, UTF-8 기준 128바이트 이하이며 Firebase Auth에는 비밀번호를 보내지 않는다. 서버가 Firebase 커스텀 토큰으로 계정을 확인하고, Firestore에는 개별 salt를 적용한 scrypt 해시를 저장한다. 원문 비밀번호는 저장하지 않는다.

닉네임과 비밀번호만 사용하는 계정은 이메일 복구 기능이 없다. 비밀번호를 잊으면 현재는 운영자에게 복구를 요청해야 한다. 닉네임은 로그인 ID로 사용하므로 옷장에서 변경할 수 없다. 브라우저의 Firebase 세션은 기기에 유지되어 같은 계정으로 재접속할 수 있다.

현재 계정 연결 단계에서 저장되는 정보는 닉네임, 분장, 지붕 색, 인트로·튜토리얼 완료 여부다. 노크·사탕·장식·방명록·실시간 접속과 랭킹은 아직 공유 저장소에 연결하지 않았다. 로그인 뒤에는 `연습 마을`로 열리고, 이 결과는 선물 순위에 포함되지 않는다. 실시간 게임과 순위 저장은 별도 단계다.

### Vercel 배포 환경 변수

`.env.example`을 참고해 Firebase Web 설정을 Vercel에 환경 변수로 등록한다. `FIREBASE_API_KEY`, 프로젝트 ID와 앱 ID는 브라우저에 전달되는 공개 설정이다. 서버 비밀값 `FIREBASE_SERVICE_ACCOUNT_JSON`에는 서비스 계정 JSON 전체를 한 줄로 넣고 Vercel에서만 보관한다. 이 JSON 키 파일은 Git에 올리면 안 된다.

Firebase에 `firestore.rules`를 배포하기 전에는 계정 기능을 공개하지 않는다. 프로필은 로그인한 본인만 읽을 수 있고, 비밀번호 해시, 닉네임 선점 문서와 로그인 시도 기록은 클라이언트에서 읽거나 쓸 수 없으며 프로필 직접 수정도 막혀 있다. Vercel 배포는 `dist/index.html`과 `api/`의 Node.js 24 함수를 사용한다.

## 현재 여러 사람이 함께 하는 게임은 어디서 도나

현재 실제 다인용 게임은 claude.ai 아티팩트에서 실행한다. 저장(db), 접속자(user), 실시간 위치·채팅(room)은 아티팩트가 주는 `window.claude` 런타임을 쓴다. Vercel 쪽에는 계정 인증과 닉네임 고유성만 연결되어 있고, 게임 결과·실시간 마을·사탕 순위는 아직 공유 저장소로 옮기지 않았다. Vercel로 열면 계정은 만들 수 있지만 게임은 `연습 마을`이며 기록은 선물 순위에 포함되지 않는다.

아티팩트에 다시 게시하는 건 코코가 한다. 고친 내용은 브랜치를 따서 PR로 올리면 머지 뒤 게시한다.

## 고칠 때

- 파일은 HTML 하나다. CSS, 스프라이트, 게임 로직이 모두 들어 있다.
- 스프라이트는 문자 격자와 팔레트로 그린다. 새 코스튬은 기존 스프라이트를 따라 하면 된다.
- 규칙 숫자(시작 사탕, 장난 시간, 기절 횟수 등)는 스크립트 위쪽 상수에 모여 있다.
- 사탕 개수는 저장하지 않고, 모두의 노크 기록을 시간순으로 다시 계산해서 낸다. 판정이 브라우저에서 나서 마음먹으면 조작할 수 있다.

## 1차 플레이 개선

- 행동 버튼, 진행 대화, 타이밍 게임이 캐릭터 위의 말풍선으로 표시된다. 위쪽 공간이 부족하면 아래로 옮기고, 화면 가장자리와 HUD를 피하도록 위치를 보정한다.
- 튜토리얼 뒤 호박 3개 수집 퀘스트가 나타난다. 수집 진행도와 첫 노크 여부는 기존 플레이어 기록으로 복원하고, 튜토리얼 완료 여부는 `guideSeen`에 저장한다.
- 노크 판정 구간은 사탕 10개 기준 28%, 최소 20%다. 속도는 기존의 60%, 입력 제한은 회차당 6초이며 성공 후 가속은 없다. 세 번 연속 성공 규칙은 유지한다.
- 튜토리얼, 내 정보, 순위 창에서 최종 사탕 순위에 따른 실제 선물 지급을 안내한다. 노크 전후에는 사탕 이동 대상을, 상점에서는 사탕 차감을 표시한다.
- 시작 안내는 캐릭터 생성 완료 알림 → 게임 목표·진행 방법 → 퀘스트 도착 알림 → 중앙 이동 가이드 순서다. 이동 가이드는 실제 이동이 시작되면 사라진다.
- 분장 완료 알림은 최대 4초 표시하며, 화면 어디든 클릭·터치하거나 Space·오른쪽 방향키를 누르면 즉시 튜토리얼로 넘어간다. 별도의 조작 안내 문구는 표시하지 않는다.
- 인트로 박스 오른쪽 아래의 ‘건너뛰기’는 이야기 연출을 취소하고 이름 입력으로 바로 이동한다. 이후 코스튬 선택과 게임 튜토리얼은 이어진다.

## 검증

검사와 로컬 서버 실행에는 Node.js 24가 필요하다. Firebase 에뮬레이터 검증에는 Java 21도 필요하다.

```sh
npm test
npm run test:emulator
```

DOM·타이머·Claude 런타임을 대역으로 사용해 튜토리얼, 퀘스트 복원, 노크 판정·제한 시간, 사탕 이동·순위, 말풍선 좌표와 두 클라이언트의 데이터 동기화를 검사한다. Firebase 에뮬레이터 테스트는 동시 닉네임 가입, 잘못된 비밀번호, 재로그인 UID 유지, 계정 프로필과 Firestore 보안 규칙을 확인한다. 실제 브라우저의 렌더링이나 Claude 서버·권한 동작을 검증하는 테스트는 아니다.

아티팩트 재게시 후 직접 확인할 항목:

- 데스크톱과 모바일에서 행동·대화·노크 말풍선이 캐릭터 근처에 뜨고 로그인 안내나 HUD에 가려지지 않는지.
- 처음 접속했을 때 시작 안내들이 순서대로 나타나는지. 인트로 글자 출력 중·문장 사이 모두 건너뛸 수 있고, 이름 입력 중 이전 인트로가 다시 나오지 않는지. 이동 가이드는 설명이 끝난 후 나타나고 실제 이동 시 사라지는지.
- 튜토리얼 완료 후 퀘스트가 뜨고, 호박 3개 수집 뒤 첫 노크 안내로 바뀌는지. 다인용 모드에서 새로고침해도 진행도가 이어지는지.
- 실제 두 계정으로 접속해 노크 성공·실패 시 양쪽 사탕과 순위가 함께 갱신되는지.
- 이벤트 종료 후 노크·상점이 닫히고 결과가 유지되는지.
